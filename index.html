          What a node stores

          Learn

          What a B-tree is, why databases use it, and how it keeps itself balanced. Read the concept, watch the video, then try it in the Visualizer.

          Concept explanation

          In short. A B-tree is a search tree built for data kept on disk. Each node fills one disk block and holds many sorted keys, so a single read narrows the search a great deal. The tree stays only a few levels deep, every leaf is on the same level, and the tree keeps itself that way: a node that gets too full is split, and a node that gets too empty borrows a key from a neighbour or merges with it.

          Why not a binary tree?

          Reading a block from a disk takes far longer than comparing keys in memory, so the number of blocks read is what counts. A balanced binary tree holds one key per node and needs about 20 levels for a million keys, which means about 20 block reads for one search. A B-tree of order 100 needs only 4 levels for the same million keys, so a search reads 4 blocks.

          Structure and rules

          The order m is the largest number of children a node may have, so a node holds at most m − 1 keys. Some books define order differently, for example through a minimum degree t. This site uses the definition that most exam questions use.

          • A node holds at most m − 1 keys, in sorted order.
          • Every node except the root holds at least m/2 − 1 keys. The root holds at least one key.
          • A node that is not a leaf and holds k keys has exactly k + 1 children. Everything inside a child is larger than the key on its left and smaller than the key on its right.
          • All leaves are on the same level.

          Search

          1. Start at the root.
          2. Look for the key among the sorted keys of the node. If it is there, stop: found.
          3. If not, and the node is a leaf, stop: the key is not in the tree.
          4. Otherwise go to the child whose range holds the key (the child number is the count of keys in the node that are smaller than the key) and repeat from step 2.

          Insert

          1. Start at the root and go down. At each node take the child whose range holds the new key, until you reach a leaf.
          2. Put the key into the leaf, in sorted position.
          3. If the leaf now has m keys, one too many, split it. The middle key moves up into the parent and the keys on either side become two separate nodes. When the node has an even number of keys there are two middle ones: this site moves up the right-hand one, and some books use the left-hand one. In an exam answer, say which you used.
          4. The parent may now be too full. Split it the same way and keep going up. If the root splits, a new root is created above it. That is the only way a B-tree gets taller, and it adds a level to every path at once, so the leaves stay on the same level.

          Delete

          1. Find the key. If it sits in an internal node, swap it with its predecessor, the largest key in the subtree to its left. The predecessor is always in a leaf, so the job becomes deleting from a leaf.
          2. Remove the key from the leaf. If the leaf still has at least m/2 − 1 keys, you are done.
          3. Otherwise the leaf is too small. If a sibling has a key to spare, borrow it: the sibling's nearest key moves up into the parent and the parent's separating key moves down into the small node. This is called a rotation. This site tries the left sibling first.
          4. If neither sibling has a spare key, merge the node with a sibling and pull the parent's separating key down between them. The parent has lost a key, so it may now be too small: repeat from step 3 one level up. If the root loses its last key, its only child becomes the root and the tree is one level shorter.

          How tall can it get?

          This site counts levels, so a single node is 1 level. Some books count edges and give a height one smaller.

          Let t = m/2, the fewest children a non-root internal node may have. A tree with N keys has at most

          1 + logt((N + 1) / 2) levels,

          and at least logm(N + 1) levels, which happens when every node is full. With order 5 and 100 keys, t = 3 and 1 + log3(50.5) is about 4.6, so the tree has at most 4 levels. It also has at least 3, because two full levels hold only 24 keys. The calculator on the COMPETITIVE EXAM page does this for any block size.

          How much work is it?

          Search, insert and delete each follow one path from the root to a leaf, and splits and merges walk back up that same path. So each reads about as many blocks as the tree has levels, which grows like log N where the base of the logarithm is the number of children per node. Inside a node the keys are sorted, so choosing the right child is quick.

          Where B-trees are used

          Database systems use B-tree indexes so that a lookup by key reads only a few blocks; the default index in PostgreSQL, MySQL (InnoDB) and SQLite is a B-tree or a B+ tree variant. File systems such as NTFS, Btrfs and XFS use them to keep directories and file extents sorted. This site simulates the plain B-tree, which is the structure exam questions describe first.

          Mistakes that cost marks

          • Using a different definition of order from the one in the question. Read it before you calculate.
          • Counting height in edges when the question counts levels, or the other way round.
          • Forgetting that the root is allowed to hold fewer keys than other nodes.
          • Not saying which key moves up when a split has two middle keys.
          • Merging when a sibling could have lent a key. Always try to borrow first.
          • Putting record pointers into the size of an internal B+ tree node. They are only in the leaves.

          Formulas

          • Most keys in a node: m − 1
          • Fewest keys, non-root node: m/2 − 1
          • Most children: m
          • Fewest children, non-root internal node: m/2
          • Most keys in h levels: mh − 1
          • Fewest keys in h levels: 2th−1 − 1, with t = m/2
          • Node fits a block: p·P + (p − 1)·K ≤ B, and with record pointers p·P + (p − 1)(K + R) ≤ B

          Key terms

          Key
          A value the tree is sorted by.
          Node
          One block of the tree: a sorted list of keys and, unless it is a leaf, one more child than keys.
          Leaf
          A node with no children.
          Order
          The most children a node may have.
          Split
          Cutting a node with too many keys in two and moving its middle key up.
          Borrow (rotation)
          Taking a key from a sibling by way of the parent.
          Merge
          Joining two small siblings and the parent's key between them.
          Predecessor
          The largest key smaller than a given key.

          What this website does

          This website teaches one topic: the B-tree, the search tree that databases use to find a record by its key. You give it numbers (the keys) and it builds a B-tree from them, one key at a time. It shows you every step: where a key is placed, when a node is too full and splits, and when a node is too empty and borrows a key or merges. You can then test yourself with a quiz, study solved exam questions, and download a report of everything you did.

          Build and change a tree, step by step

          1. Choose the Order. The note under the boxes tells you how many keys and children a node may have.
          2. Click in the Keys box and type one or more numbers.
          3. Press Insert (or press Enter). The steps play by themselves. The key you are placing travels down the tree to its leaf.
          4. To remove keys, type them and press Delete. To look for keys, type them and press Search. Search never changes the tree.
          5. When the steps stop, read the sentence under the figure. It says what the last step did.
          6. To see it all again, press First step and then Play. To go one step at a time, press Next step or the right arrow key.
          7. Made a mistake? Press Undo. Redo puts the change back.
          8. Want a ready-made demonstration? Press one of the Examples, such as “Root splits twice”. It sets up the tree, plays it and explains what to look for.

          How the processing takes place

          1. When you press Insert, Delete or Search, the page hands each key to the B-tree engine, a program that follows the textbook rules for order m.
          2. The engine does the work one small move at a time and writes down a step after each move: a copy of the whole tree, a sentence saying what happened, and the nodes involved.
          3. The page then plays those steps back. The pseudocode beside the figure shades the lines the current step is carrying out, so you can match each move to the algorithm.
          4. After every action the page checks the rules of a B-tree: keys in order, no node too full or too empty, one more child than keys in every internal node, and all leaves on the same level. The result is reported under “This tree”.

          How to read the output

          • The figure. Each box is a node and each cell holds a key. Lines go from a node to its children. The leaves are all on the bottom level.
          • Yellow marks the node or key the current step is about. Blue marks nodes the search has already passed through. A small tag above the figure carries the key you are placing.
          • The count on each node is keys held out of the most allowed. It turns red when a node is too full, which is about to cause a split, and amber when it is too empty, which is about to cause a borrow or a merge.
          • The sentence under the figure has a coloured label: blue for walking down or searching, green for a key placed or found, amber for a split, borrow or merge, red for a delete or a message that nothing could be done.
          • This tree gives the number of keys, nodes and levels, and says whether all the rules hold. Selected node describes any node you click. History lists what you did, newest first.
